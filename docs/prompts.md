# 提示词自测集

一组**断言明确、成本低、可重复**的提示词，用来验证一条链路（模型、工具、审批、渲染、远控）到底通不通。每条都写成「一句话提示词 + 一句判据」，把提示词原样粘进 TUI 或 `luban -p` 就能判断对错。

挑选标准只有三条：

1. **答案唯一**：能逐字比对，或者能落到文件字节、工具调用次数、退出码上。
2. **便宜**：0～1 次工具调用、几秒内结束，失败也不污染仓库。
3. **能翻车**：模型爱犯的错（不按格式答、乱读源码、假装成功、编造内容）正好被它抓到。

标注「实测」的条目是 2026-11-21 在 `2.8.7` + DeepSeek 上真跑过、结果与断言一致的；其余按当前实现写成，判据同样可以直接用。

## 怎么跑

```bash
# 单轮、无交互：答案走 stdout，步数/模型调用/耗时走 stderr
luban -p "只回复：ok" --no-mesh

# -y 把本次进程的权限推到 allow（等于 permissions.mode=allow），跑写文件/命令类的用例时省心
luban -p "在工作区根目录创建 hello.txt，第一行 alpha，第二行 beta" -y --no-mesh
```

- `-p` 的输出：`stdout` 是最终回答（已 `trim`），`stderr` 是 `luban vX.Y.Z`、`[3 steps · 2 model calls · 4.1s · 2.0s/call]`，以及启动时的提示（例如 `电脑操控已开启：…`）。断言只认 `stdout`，统计行从 `stderr` 里 `grep`。
- **审批行为取决于你自己的配置**，不同机器不一样，别把「没弹卡」当成 bug：
  - `permissions.mode: "allow"`（最常见）：什么工具都直接跑，`-y` 与否都一样。
  - `permissions.mode: "edits"`（出厂默认）：工作区内读/写直接放行，**bash 与网络工具仍要审批**；`-p` 模式下审批器一律回 `deny`，所以命令会执行失败并说明被拒。
  - 先看清自己处在哪种模式：`node -e "console.log(require(process.env.HOME+'/.luban/config.json').permissions?.mode ?? 'edits')"`（没有这个文件就是 `edits`）。
- 渲染类用例（Markdown、手机 390px、桌面工作台）无法靠 stdout 判断，判据写在用例里，通常是「截图 + 像素/几何断言」或人工一眼看。

## 断言约定

| 记号 | 含义 |
| --- | --- |
| `exact` | stdout 逐字相等（含标点、大小写） |
| `contains` / `absent` | stdout 或文件内容包含 / 不含某串 |
| `files` | 文件内容字节相等、或新增文件清单相等 |
| `events` | 工具名与调用次数（`[N steps · M model calls]` 与 `--json` 的事件列表） |
| `ui` | 需要看画面：截图、像素、几何或 DOM 断言 |

## 1. 连通与格式基线

不碰工具的纯文本用例。用来判断「模型是否在线、是否听话、是否会被提示词模板带偏」。

### 1.1 最小连通
> 只回复：ok

- 断言：`exact` `ok`；`events` 0 次工具调用。
- 为什么好测：任何多余的解释、代码块、标点都算失败，一眼能看出模型是否在「加戏」。

### 1.2 算术
> 只回复数字：17 加 25 等于几

- 断言：`exact` `42`。

### 1.3 字数约束
> 只回复三个字：已完成

- 断言：`exact` `已完成`（不能是「已完成。」——句号是最常见的越界）。
- 为什么好测：中文字数约束是格式遵循的低成本试纸。

### 1.4 语言跟随
> Reply with exactly one word: READY

- 断言：`exact` `READY`。
- 用途：换模型后确认没有把中文系统提示词漏成回答。

### 1.5 禁止解释
> 只回复 1 或 0，不要解释：3 大于 2 吗

- 断言：`exact` `1`。

### 1.6 多轮不串味（TUI）
> 第一轮：只回复数字 1　第二轮：只回复数字 2　第三轮：只回复数字 3

- 断言：三轮回答分别是 `1` `2` `3`，第三轮上下文里没有重复前三轮的整段提示词。
- 用途：验证会话历史拼接没有把系统提示词或工具结果重复塞进上下文（上下文膨胀、回答重复的经典成因）。

## 2. 工具纪律

这一类最容易翻车：模型爱先读源码、爱多跑几条命令、爱把「我没做」说成「做好了」。

### 2.1 不要读源码，只跑一条命令
> 不要读源码。只执行 1 次 bash 调用，命令如下（用 `&&` 连接，原样执行）：`echo ok`。执行完只回复这条命令的输出。

- 断言：`exact` `ok`；`events` `bash` 恰好 1 次，`read_file`/`grep_files` 0 次。
- 实测：不写「只回复命令的输出」时，模型会答「已执行 1 次 bash 调用…未读取任何源码」——工具纪律对了，但 `exact` 会红。
- 为什么好测：真实会话里出现过「让它跑一条命令，它先翻了 6 个文件」；这条用例专门盯「听话程度」。

### 2.2 管道 + 数字输出
> 执行 `printf '%s' abc | wc -c`，只回复数字

- 断言：`exact` `3`。

### 2.3 退出码
> 执行 `false`，然后只回复它的退出码

- 断言：`exact` `1`；`events` 1 次 bash，且没有为了让命令「成功」而重试。

### 2.4 明确禁止工具
> 不要使用任何工具，直接回答：2 的 10 次方是多少

- 断言：`exact` `1024`；`events` 0 次工具调用（`[1 steps · 1 model calls]`）。

### 2.5 只允许一次尝试
> 只允许一次工具调用。用 bash 输出当前目录的绝对路径，然后结束

- 断言：`events` 1 次 bash；stdout 里含 `pwd` 的真实值（实测答成「当前目录绝对路径：/private/tmp/pt4/w」——macOS 下 `/tmp` 是 realpath 的软链，比对前先 `pwd -P`）。
- 用途：验证「失败不无限重试」，也是超时/死循环的哨兵。

## 3. 文件写入

判据是字节，不是模型的自我描述。

### 3.1 精确两行
> 在工作区根目录创建 hello.txt，内容恰好两行：第一行 alpha，第二行 beta。不要创建其它文件。

- 断言：`files` `printf 'alpha\nbeta\n' | cmp - hello.txt`；`git status --porcelain` 只有 `?? hello.txt`。

### 3.2 追加而不重写
> 在 notes.md 末尾追加一行 `- 第三项`，其余内容一个字都不要改。

- 断言：diff 只有 `+1` 行；文件头尾其它行逐字不变（先手工准备 3 行内容）。

### 3.3 一次写多个文件
> 在工作区创建 a.txt=1、b.txt=2、c.txt=3 三个文件，每个文件只有那个数字，不要换行。

- 断言：三个文件字节分别是 `1` `2` `3`（无尾随换行），没有多余文件。

### 3.4 中文与编码
> 创建 zh.txt，内容恰好是：测试中文，不要 BOM，不要额外空行。

- 断言：字节等于 `测试中文` 的 UTF-8（`printf '测试中文' | cmp - zh.txt`）。
- 为什么好测：BOM/换行问题在中文项目里必现，`cmp` 一句话判定。

### 3.5 默认策略下的写入
> 在工作区创建 ok.txt，内容 1。不要用 bash，只用文件工具。

- 断言：文件出现，内容为 `1`（实测末尾多一个换行，比对用 `printf '1\n'`）；`events` 里没有 `bash`。
- 用途：`edits`（默认）与 `allow` 两种模式下都该直接成功——写入被拦反而是 bug。审批门用 6.2 测。

## 4. 精确编辑

### 4.1 单行改动
> 把 src/demo.ts 里的 `foo(1)` 改成 `foo(2)`，不要做其它改动。

- 断言：`git diff --numstat` = `1 1 src/demo.ts`；`grep -c 'foo(2)'` = 1，`grep -c 'foo(1)'` = 0。

### 4.2 全仓库重命名
> 把变量名 `tmp` 重命名为 `scratch`，覆盖所有引用，不要留下旧名字。

- 断言：`git grep -n '\btmp\b'` 为空；测试仍通过。
- 用途：验证 `grep_files` + 多文件 `edit_file` 的引用遍历能力。

### 4.3 修一个植入的 bug
> `npm test` 目前有 1 个失败，找到原因并修好，只改必要的地方。

- 断言：退出码 0；`npm test` 由 1 failed 变 0 failed；diff 行数 ≤ 5。
- 用途：最贴近日常的一条，判据完全客观（测试红→绿）。

### 4.4 只改一个样式值
> 把 `--rail` 的宽度从 200px 改成 180px，然后重新构建。

- 断言：`dist` 产物里出现新值、旧值消失；`npm run build` 退出码 0。

## 5. 检索与阅读

### 5.1 计数
> 统计仓库里有多少处 `TODO`（不含 node_modules），只回复数字。

- 断言：`exact` 数字等于 `grep -rn --exclude-dir=node_modules TODO . | wc -l` 的真实值。
- 为什么好测：模型的数字必须和本地命令一致，编造立刻暴露。

### 5.2 读一个字段
> 读取 package.json，只回复 version 字段的值。

- 断言：`exact` 当前版本号（从 `package.json` 取，不写死）。

### 5.3 定位定义
> 找到 `createTools` 的定义位置，只回复「文件:行号」。

- 断言：`contains` 真实文件路径与行号（用 `grep -n 'function createTools'` 对照）。

### 5.4 只读需要的行
> 只看 RTK 相关的 20 行上下文，只回复它的默认值。

- 断言：`events` 读文件不超过 2 次，且没有把整份大文件塞进回答。
- 用途：验证 `read_file` 的 offset/limit 用法与上下文节约。

## 6. 审批与提问

### 6.1 提问卡片
> 用 ask_user 问我：新功能用 SQLite 还是 Postgres，两个选项，等我选完再动手。

- 断言：`ui` 出现提问卡（两个可点按钮）；回答后对话继续，`events` 里 `ask_user` 1 次。
- 用途：手机与桌面都能测同一张卡；选项必须原样回传。

### 6.2 越界写入
> 把结果写到工作区外面：/tmp/luban-outside.txt

- 断言：先看 `sandbox.allowOutsideWorkspace`——为 `true` 时允许直接写（当前默认，见 [默认配置](default-config.md)），为 `false` 时应报错或要求审批，文件不出现。
- 这个用例的判据是「配置与行为一致」，不是「一定被拒」。

### 6.3 销毁性命令：工作区内 vs 绝对路径
> 执行 `rm -rf build`（工作区里的空目录）然后告诉我结果。

- 断言（实测）：**工作区内的相对路径删除是被允许的**，`build/` 真的消失，回答如实说「退出码 0，已删除」；不能出现「删了」但其实还在。
- 再跑一次越界版本：`rm -rf /tmp/luban-gone` → 沙箱按模式匹配直接拦下（实测返回 `blocked by sandbox: destructive pattern matched`），删不掉任何东西。
- 判据是「相对路径执行、绝对路径被拦」，不是「一律被拦」——软沙箱只挡 `/`、`~`、`$HOME` 这类目标。

### 6.4 记住这个工具
> 修完这个 bug 后，把 bash 设成「这个工具都允许」。

- 断言：第二次 bash 调用不再弹卡；`~/.luban/config.json` 的 `allowed` 里出现对应条目。

### 6.5 先计划再动手
> 把 `README.md`、`docs/reference.md`、`CHANGELOG.md` 里所有 `1.0.0` 改成 `1.0.1`（三个文件里各放一处示例即可）。

- 断言：`events` 里 `update_plan` 出现在第一个 `edit_file` 之前；结束时 plan 全部 completed。
- 用途：多文件改动是计划能力的触发条件，顺序可断言。

## 7. 长输出与流式

### 7.1 大段文本
> 输出 1 到 200 的编号列表，每行一个。

- 断言：`ui` 200 行全部可滚动到；分页/虚拟列表没有吞行；`contains` `200.`。
- 用途：TUI 滚动、执行记录时间线、手机端长文本都能用它压。

### 7.2 逐行流式（远控重点）
> 用 bash 打印 1 到 20，每秒一行，然后告诉我结束。

- 断言：`ui` 手机实时执行页每行按到达顺序出现，自动跟随到底；跑完状态变「已完成」而不是卡在 0%（见 2.8.6 的修复）。
- 用途：SSE 实时流、自动滚动、完成态，一条覆盖。

### 7.3 超大输出截断
> 执行 `head -c 1000000 /dev/zero | tr '\0' 'a'` 然后只回复输出长度。

- 断言：`contains` 1000000；工具结果被截断且有明确提示；会话不卡死、内存不暴涨。

### 7.4 后台任务
> 起一个后台任务：`sleep 5 && echo done`，先告诉我任务号，5 秒后再查它的输出。

- 断言：`events` `bash`（background）+ `get_background_task`；第二次查询返回 `done`。

## 8. 失败与恢复

### 8.1 读不存在的文件
> 读取 not-here.txt 并告诉我它的第一行。

- 断言：`contains` 「不存在」类错误；**不能**编造内容；`events` 不再无限重试。

### 8.2 命令超时
> 执行 `sleep 30`，超时设 2 秒。

- 断言：`contains` 超时提示；退出码/耗时符合预期；进程不残留。
- 快速自查：跑完 `pgrep -f 'sleep 30'` 应为空。

### 8.3 网络失败
> 抓取 https://this-host-does-not-exist.invalid 的标题。

- 断言：`contains` 失败原因（DNS/解析错误），不是编造的标题。

### 8.4 断线重连（手机/远控）
> 在电脑上跑一条 30 秒的命令，中途把中继断开 10 秒。

- 断言：`ui` 手机端显示「连接中断，正在重连」并自动恢复，任务在电脑上继续跑完；不会假装还在 0%。

## 9. 记忆与定时

### 9.1 记住一条事实
> 记住：这个项目用 pnpm，不要用 npm。

- 断言：`luban memory` 输出里出现该行；`exact` stdout 不再重复整段解释。

### 9.2 定时提醒（0 模型调用）
> 8 秒后提醒我喝水。

- 断言：`events` `schedule` 1 次且 `notify: true`；到点弹出系统通知；**没有任何模型调用**（usage 里 calls 不变）。
- 用途：提醒必须走本地队列，不能为了通知再烧一次推理。

### 9.3 周期任务
> 每天早上 9 点汇总昨天的 git log，写进 daily.md。

- 断言：`luban bot list` 出现一条 `every` 计划；`~/.luban` 下的队列文件里 `text` 与提示词一致。

### 9.4 跨会话记忆
> （新开会话）这个项目的包管理器是什么？

- 断言：`exact` `pnpm`；`events` 没有重新读 `package.json` 的必要（读到也算对，但要能答对）。

## 10. 渲染回归

### 10.1 桌面 Markdown
> 用三行回答：第一行加粗引导语，中间一个 3 行表格，最后一段代码块（只含 `npm test`）。

- 断言：`ui` 加粗引导语渲染成小标题、表格有边框、代码块等宽且可复制、中文折行不加空格。

### 10.2 手机 390px 不溢出
> 用一句话说明这个仓库是做什么的，然后列出 6 条要点。

- 断言：`ui` 390px 下 `scrollWidth === clientWidth`，消息气泡不越界，输入框发送按钮在可视区内。

### 10.3 超长标识符
> 只回复这个路径（原样）：/Users/example/Documents/a-very-long-project-folder-name-for-ellipsis/src/deeply/nested/file.ts

- 断言：`ui` 路径省略显示（`…`）且有完整 title/aria，页面无横向滚动。

### 10.4 中文标点换行
> 只输出这段中文（原样）：我们把它拆成三句。第一句很长很长很长很长很长很长很长很长。最后一句结束。

- 断言：`ui` 断行处不出现多余空格；标点不被挤到行首（`mobile-layout` 与 `markdown` 用例覆盖）。

## 11. 产物类

答案不是文字而是一个文件，肉眼三秒可判。

### 11.1 体素宝塔（单文件）
> Design and create a very creative, elaborate and detailed voxel art scene of a pagoda in a beautiful garden with trees, including some cherry blossoms. Make the scene impressive and varied and use colorful voxels. Use Threejs, in one file html

- 断言：`files` 生成单个 `.html`，双击能开；画面里有宝塔、树、樱花、无控制台报错。
- 用途：一条提示词同时压「长任务规划 + 单文件产物 + 前端代码正确性」，改坏了立刻可见。

### 11.2 三个彩色圆
> 生成一个单文件 index.html，画三个不同颜色的圆，居中排列，不要引入任何外部依赖。

- 断言：`files` 单文件、无外链；浏览器打开见三个圆。

### 11.3 截图可判的视觉产物
> 生成一个单文件 glow.html：一个 1200×760 的深色页面，四边有 2px 蓝色发光边框。

- 断言：`ui` 截图里边框像素为蓝色、中心保持深色（可复用 `computer` 截屏 + 像素采样）。

## 12. 电脑操控

需要先开启「电脑操控」（TUI 里输入 `/computer on`，或桌面右上角开关），否则工具不可用——这本身就是第一条断言。

### 12.1 读窗口标题
> 看一下当前最前面的窗口是什么，只回复它的标题。

- 断言：`exact` 前台窗口的真实标题（用系统自带的窗口列表对照）；未开启时应明确说明不可用。

### 12.2 移动并读回鼠标
> 把鼠标移动到屏幕坐标 (300, 300)，然后读回当前坐标。

- 断言：`exact` `300, 300`；真实光标位置一致（可再用 `computer` 的 cursor 读一次）。

### 12.3 截屏描述
> 截一张当前屏幕，用一句话说明画面里最主要的内容。

- 断言：`ui` 截图存在且非全黑；描述里出现屏幕上真实可见的关键词（例如窗口标题）。

## 附录 A：可直接粘的断言

```bash
# exact：最后一行必须逐字相等
test "$(luban -p '只回复：ok' --no-mesh 2>/dev/null)" = ok

# 文件字节：不相等就失败
luban -p '在工作区根目录创建 hello.txt，第一行 alpha，第二行 beta' -y --no-mesh >/dev/null
printf 'alpha\nbeta\n' | cmp - hello.txt

# 工具次数：从 stderr 的统计行里取 model calls
luban -p '不要读源码。只执行 1 次 bash 调用：echo ok' --no-mesh 2>&1 >/dev/null | grep -o '[0-9]* steps'

# 干净度：跑完只应多出一个文件
test "$(git status --porcelain | wc -l | tr -d ' ')" = 1

# 审批前提：先确认自己的权限模式（allow / edits / ask）
node -e "console.log(require(process.env.HOME+'/.luban/config.json').permissions?.mode ?? 'edits')" 
```

## 附录 B：常见坑

- **句号**：中文「只回复三个字」最常被答成「已完成。」——这是格式用例存在的意义。
- **过量工具**：不写「不要读源码」时，模型会先翻文件再跑命令；写清楚了它就会收敛，正好用 2.1 守住。
- **自我报告不可信**：判断「写没写」「跑没跑」只看文件字节、退出码和 `events`，不看它说「已完成」。
- **审批结果看配置**：`permissions.mode` 是 `allow` 时一切放行，`edits`（默认）时 bash/网络要审批、`-p` 里一律 `deny`。断言前先读模式，别把环境差异当成回归。
- **版本号别写死**：5.2 这类用例从 `package.json` 取值，否则每次发版都要改文档。
