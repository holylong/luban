# 思考流输出闪烁排查（v1.16.104）

## 原因与复现

旧的 `windowsOutput` 只在 `win32` 的交互终端启用行更新。Linux 仍直接接收 Ink 标准渲染器的“擦除上一帧，再写入新帧”序列。即使界面高度固定、没有 `ESC[2J` 全屏清除，每次思考更新仍会产生几十条 `ESC[2K` 行擦除。不能原子呈现同步更新的终端可能显示擦除与重画之间的空白。

在真实 App 树上模拟模型逐段发送思考，接入与 CLI 相同的输出代理后，旧代码的 Linux 路径稳定触发行擦除测试失败，Windows 路径通过。旧的布局测试只检查高度、光标漂移和全屏清除，未检查持续思考过程中的整帧行擦除。

## 修改与边界

- 将代理改为 `terminalOutput`，所有交互 TTY 都使用固定高度帧的行更新，无需更改 Ink 的标准渲染器和尾随换行约定。
- 保持吉祥物背景先合成、再比较终端行的顺序；保留未变化的历史、计划和背景行。
- 改变尺寸、外部输出、未知控制序列、二进制写入时回退并重新建立基准；屏幕阅读器和重定向输出不使用代理。
- 不启用 Ink 的增量渲染器，避免已有的光标逐行漂移问题。

## 验证

回归测试使用模拟 TTY 和真实 Ink 输出，覆盖 60、100、160 列，连续中文、换行、长思考行、emoji，以及吉祥物输出链。稳定流式阶段要求没有整帧行擦除或全屏清除、没有重发已有历史；现有测试继续验证输入行定位及窗口缩放后的恢复。

这验证了输出序列和布局；实际终端的视觉表现仍取决于终端实现。首次绘制和窗口缩放可能仍走完整重画路径。
