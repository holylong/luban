# 界面排版复用（1.16.101）

流式回答更新时，终端原本会把历史消息与当前回答合成新数组，再对全部内容解析
Markdown、生成执行行并换行。网页和桌面端共用的 Transcript 则会收到事件重放后
新建的历史条目，重复生成未变化条目的 React 子树、Markdown 和语法高亮节点。

## Pretext 评估

检查父目录 pretext 的本地提交 `0a27bbe0`、公开 API 和 Markdown 聊天示例。
[Pretext](https://github.com/chenglou/pretext) 把文字分段、Canvas 字宽测量放在
`prepare()`，然后复用测量结果计算布局。它不负责 React 协调或 DOM 差异更新。

在 Node.js 22.19.0 直接调用本地源码编译后的 `prepare()`，报错
`Text measurement requires OffscreenCanvas or a DOM canvas context.`。
终端需要字符列宽，Canvas 的像素字宽也不能代替它。网页/桌面端可以使用该库，
但当前主要重复的是 React/Markdown 计算，并没有逐条测量 DOM 高度的流程；单独
加入 Canvas 测量不会自动解决这个问题。因此本次采用预处理、复用未变结果的
思路，没有新增 Pretext 依赖，也未修改父目录的 Pretext 项目。

## 变化

- 终端将历史记录和当前输出分开。只有历史内容、详情模式、终端宽度或活动记录
  变化时才重建历史排版；流式回答仍完整解析，正确处理后续闭合的代码围栏和强调。
- 每个挂载视图只保留一份当前历史排版；切换会话和宽度时替换，不积累历次缓存。
- 历史行对象保持稳定，行组件可复用。主题修订号显式触发重绘，选区变化正常更新。
- 网页和桌面共用的记录组件按可见字段判断变化。事件重放生成新对象时，未变化的
  历史内容跳过重新渲染；工具状态、命令参数、输出、耗时和编辑记录变化正常刷新。
- Markdown 和代码行组件单独复用，保留 DOM、卡片展开状态、文本选择和浏览器查找。

Ink 仍会布局当前视口并输出终端帧；网页仍会布局实际改变的 DOM。本次没有替换
渲染器，也没有把长历史从 DOM 中卸载。文件修改记录和会话持久化均保持完整。

## 测量

终端基准：Linux、Node.js 22.19.0，90 列，中英文混合、代码围栏，当前输出不断
变化。每组 120 次，前 20 次预热，计时包含历史构建和物理行生成。历史预处理的
首次成本不包含在稳态数字中。`npm run build && node scripts/transcript-bench.mjs`
可复现，并校验两种实现的行内容一致。

| 历史消息 | 物理行 | 原方式 p50 | 复用后 p50 |
| --- | ---: | ---: | ---: |
| 100 | 1350 | 0.957 ms | 0.008 ms |
| 500 | 6750 | 4.840 ms | 0.010 ms |
| 2000 | 27000 | 21.148 ms | 0.069 ms |

浏览器基准：生产构建 React，将实际 Transcript 组件直接挂载到 Headless Chromium，
放入 500 条带中英文、强调、代码高亮的历史消息，每帧重建条目对象并更新最后一条
回答，模拟事件重放。每轮 80 帧、预热 20 帧，交替加载修改前/后构建，各测两轮：

| 实现 | p50，两轮 | p95，两轮 |
| --- | --- | --- |
| 修改前 | 19.5 / 19.5 ms | 41.2 / 36.8 ms |
| 修改后 | 0.3 / 0.2 ms | 0.4 / 0.3 ms |

浏览器数据是同步 React 提交及组件自身滚动效果的耗时，未加载完整工作台 CSS、
其他面板或真实 SSE 网络。终端数字也不包含 Ink 输出和终端模拟器绘制，均不能
解释为整个应用或模型回答的加速倍数。网页与桌面共享修改后的代码路径；尚未在
原生 Windows/Electron 上做相同的性能测量。

## 验证

覆盖当前输出变化时复用历史、Markdown 后续语法闭合、宽度/会话失效、恢复的编辑
记录、工具元数据更新。真实浏览器检查工具执行中到完成、折叠状态保留、已展开
编辑差异更新、HTML 转义和历史 DOM 保持。原有主题切换、Mesh、本地对话、终端
重绘、鼠标、滚动和内存限制回归继续通过。
